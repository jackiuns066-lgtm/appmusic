# کلیدهای امضای اپلیکیشن Novo

اندروید اجازه نمی‌دهد نسخه‌ای با **کلید امضای متفاوت** روی نسخهٔ نصب‌شده به‌روزرسانی شود؛
خطای `App not installed as package conflicts with an existing package` دقیقاً همین است.

در گیت‌هاب، هر اجرای بیلد قبلاً یک کلید debug **تصادفی و تازه** می‌ساخت (چون ماشین‌های
GitHub همیشه نو هستند). نتیجه: هر APK جدید امضای متفاوتی داشت و روی نسخهٔ قبلی نصب نمی‌شد.
برای همین دو کلید ساخته شده است:

| فایل | کاربرد | وضعیت | رمز |
|---|---|---|---|
| `novo-debug.p12` | امضای بیلدهای **debug** در CI و روی سیستم خودتان | ✅ در مخزن کامیت شده (کلید debug، محرمانه نیست — رمز استاندارد اندروید: `android`) | alias: `androiddebugkey` |
| `novo-upload.p12` | امضای **نسخهٔ انتشار** (آپلود در گوگل‌پلی/کافه‌بازار/مایکت) | ⛔️ هرگز کامیت نمی‌شود؛ فقط در Secrets گیت‌هاب | در فایل `CREDENTIALS.txt` (در فضای کاری، کامیت نمی‌شود) |

## چرا کلید debug در مخزن commit شده؟

این کلید **محرمانه نیست** (رمز پیش‌فرض کلید debug اندروید همیشه `android` است) و فقط برای
این است که همهٔ APKهای تستی یک امضای ثابت داشته باشند تا روی هم نصب شوند.
برای انتشار عمومی، حتماً از `novo-upload.p12` استفاده کنید.

## تنظیم کلید انتشار روی GitHub (یک‌بار، ۴ Secret)

1. فایل `keystore/CREDENTIALS.txt` را از فضای کاری باز کنید. مقدار **BASE64** و **رمز** داخل آن است.
2. در گیت‌هاب به این مسیر بروید:
   `Settings → Secrets and variables → Actions → New repository secret`
3. این چهار Secret را بسازید:

| نام Secret | مقدار |
|---|---|
| `NOVO_KEYSTORE_BASE64` | کل محتوای BASE64 در `CREDENTIALS.txt` (یک خط طولانی) |
| `NOVO_KEYSTORE_PASSWORD` | رمز نوشته‌شده در همان فایل |
| `NOVO_KEY_ALIAS` | `novo-upload` |
| `NOVO_KEY_PASSWORD` | همان رمز |

4. بعد از این کار، هر بیلد **دو فایل** می‌دهد:
   - `my-app-apk` → نسخهٔ debug
   - `my-app-release-apk` → نسخهٔ release امضاشده با کلید خودتان (مناسب انتشار و تست واقعی)

> اگر این Secrets را تنظیم نکنید، بیلد باز هم کار می‌کند و نسخهٔ release به‌صورت خودکار با
> همان کلید debug امضا می‌شود تا حتماً روی گوشی نصب شود.

## ⚠️ نکته‌های مهم

- **از `novo-upload.p12` و رمزش نسخهٔ پشتیبان نگه دارید** (روی فلش/فضای ابری شخصی). اگر این
  کلید را گم کنید، دیگر نمی‌توانید برای همان اپ در استورها آپدیت منتشر کنید (مگر با Play App Signing
  و درخواست تغییر کلید آپلود).
- این فایل‌ها در `.gitignore` هستند و در مخزن **عمومی** قرار نمی‌گیرند.
- اثر انگشت کلید در لاگ هر بیلد (مرحلهٔ `Show signing certificates`) چاپ می‌شود؛ اگر در همهٔ
  بیلدها یکسان بود، نصب روی نسخهٔ قبلی بدون خطا انجام می‌شود.
